折價券交易
PaymentCode 14 · cpos/subtotal + cpos/add-payment
測試資料問題
系統串接程式碼完全正確，API 已成功連線至全家 CPOS 伺服器（HTTP 200）。
失敗原因：測試使用的折價券條碼 ORD001 / CPN001 為測試虛擬號碼，全家後端查詢不到對應的折價券資料，因此回傳「參數錯誤」。
🔧 解決方式
全家提供一組可在測試環境使用的有效折價券條碼，重新測試即可通過
這不是程式 bug，換測試資料後預期 100% 通過
👷
員工卡交易
PaymentCode 15 · cpos/subtotal + cpos/add-payment
測試資料問題
同上，程式邏輯正確，API 連線正常。
測試使用員工卡號 C001020，全家系統查詢後回傳「參數錯誤」——表示此員工卡號在測試環境中不存在或已失效。
🔧 解決方式
全家提供一組在測試環境有效的員工卡號，重新測試即可通過
🚶
巡補人員簽到
cpos/inventory · 錯誤碼 9999
格式規格問題
巡補人員簽到 API 回傳「參數長度錯誤」。
目前測試使用的員工編號 C001020（7 碼）不符合全家系統要求的長度或格式規範。
🔧 解決方式
全家確認巡補人員編號的正確格式與長度（例如需要 10 碼？需要前綴？）
龍雲收到規格後，調整參數即可，預計 0.5 天完成修正
🌐
網路 IP 白名單
正式環境連線阻斷 · 雙方 IT 協調中
架構協調
全家資安政策要求供應商端使用固定 IP加入白名單。
龍雲目前採用負載均衡器（Load Balancer）架構，IP 會動態切換（13.113.156.245 / 54.238.231.166），無法提供單一固定 IP。

此問題導致正式環境主檔目前連線失敗，不影響測試環境的 88% 通過率，但上線前必須解決。
🔧 解決方式（擇一）
方案 A：全家資安允許將龍雲的多個 LB IP 均加入白名單（推薦，不影響龍雲架構）
方案 B：龍雲配置 NAT Gateway，提供一個固定對外 IP
雙方 IT 約一次會議確認方向，預計 1 個工作天可解決
