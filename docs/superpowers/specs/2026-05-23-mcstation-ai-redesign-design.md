## 背景與問題診斷

### Gmail 客戶詢問模式（近 90 天分析）
共 7+ 件真實詢問，來自 service@transtep.com 的資料：

| 客戶 | 需求類型 | 問題 |
|------|---------|------|
| 陳俞瑄 | 公司客戶用販賣機/租賃/複合式 | 資訊極少 |
| Reckitt Angela Chen | 品牌商：益節/杜蕾斯等品牌想上架 | 要求看服務簡報、安排拜訪 |
| 美萌科技 | 90人公司設置販賣機 | 一行描述 |
| 優仕全球資源 | 冷凍型機台在園區和校園 | 一行描述 |
| 展望運動 | 體育場館設置 | 一行描述 |
| 富田電機 | 科學園區餐飲空間評估 | 等了近2天無人回覆再追問 |
| 豆乳雞 | 詢問客製化現炸機台 | 被直接回絕 |

**共同問題：**
1. 表單太簡單 → 收到資訊太少 → 業務要反覆電話追問
2. 客戶不了解 MCS 完整服務範圍
3. 現有網站太長，沒有頂部分類，業務 demo 時很尷尬
4. 3 種客戶類型（場地主/品牌商/客製化）需要完全不同的溝通邏輯

## 已確認決策

### 1. 分類維度：按客戶角色
```
我是場地主  ｜  我是品牌商  ｜  我要加盟合作  ｜  我要客製化
```

### 2. 方案：方案一 — 完整改版「對話驅動官網」

完整改版 mcstation.ai，以 AI 對話為核心互動模式。不做疊加式修改。

### 3. 介面佈局
- **PC（桌機/筆電）**：左右分割 — 左側 60% 動態內容面板 + 右側 40% AI 對話
- **手機（主力入口）**：全螢幕沉浸式 Chat（模糊背景疊層）
- 同一套 Next.js code，RWD 自動切換

### 4. 網站同時服務兩個使用情境
- **客戶自助**：陌生客戶自己找來，被 AI 引導填資料、上傳照片
- **業務 Demo 武器**：Henry 帶著筆電拜訪 Reckitt，打開網站，點「我是品牌商」，左側立刻變成品牌商版 Pitch Deck，右側 AI 現場問答

## 技術架構（待 CTO 確認細節）

### 前端
- **框架：** Next.js 15 App Router（延續現有）
- **新增路由：** `/consult` + query param `?role=venue|brand|franchise|custom`
- **AI Chat：** Vercel AI SDK `useChat` hook（streaming）
- **動態左側面板：** React state 根據對話階段切換 component
- **上傳：** 原生 `<input type="file">` + 預覽，檔案上傳至 S3 或 Vercel Blob

### 後端
- **`/api/chat` route：** Streaming，使用 Gemini 2.5 Flash（已有 API Key）
- **System prompt：** 每個角色有獨立 system prompt + 產品知識庫
- **結構化資料萃取：** 對話結束時萃取 lead 資訊（JSON）
- **通知：** Lead 資料 → Email 通知業務（henry.ho@transtep.com）

### AI 進化機制（ai-advisor 精神）
- 每次對話完整記錄（DB）
- Jason/業務可 review 對話，標記好/壞回應
- 定期更新 system prompt 加入學到的模式
- 追蹤「哪些問題 AI 答不好」→ 加入知識庫
