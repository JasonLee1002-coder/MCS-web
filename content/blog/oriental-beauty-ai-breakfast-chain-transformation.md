## 台灣早餐市場的AI轉折點

台灣早餐店市場每年產值約 **2,000 億元**，全台店家突破 19,000 家。但在這個看似龐大的市場背後，連鎖業者面臨著近乎矛盾的困境：

- 外送平台抽成高達 **35%**，嚴重侵蝕利潤
- 尖峰時段（07:00–09:00）出餐壓力極大，漏單、錯單頻發
- 門市備貨高度依賴店長「直覺」，過度備料與缺料問題並存
- 人力短缺、流動率高，知識傳承靠口傳，新人訓練週期長達 3–4 週

東方美實業股份有限公司，作為台灣連鎖早餐業的代表品牌之一，選擇了一條不同的路：**全面導入 AI，從根本改變門市營運模式**。

## 銓幻元的角色：不只是設備供應商，更是AI整合夥伴

銓幻元科技（MCS）在這次合作中，提供的不是單一產品，而是一套**從前台到後台、從門市到總部的完整 AI 整合方案**，核心架構包含三大層次：

### 1. GraBox 智取櫃 × 前台體驗升級

東方美門市導入 **GraBox AI 智取櫃（My Express）**，顧客透過 APP 點餐後掃 QR Code 或簽名即可自助取餐，完全不需等候人工叫號。

駁二精緻餐酒館新品牌更進一步導入：
- **AI 多國語言 Kiosk**（中/英/日等多語言自助點餐）
- **WiXGo 掃碼點餐**：免下載 APP，手機掃 QR Code 即可點餐付款
- **AI 商品推薦三重演算法**：結合熱銷品項、顧客偏好、天氣與時段，自動推薦加購商品，有效提升客單價

### 2. AI 超級店長：A2A 代理人協作架構

這是整個案例最關鍵的創新。銓幻元為東方美導入「**AI 超級店長**」，這是一套基於 A2A（Agent-to-Agent）架構的 AI 代理人系統，分為兩個自治層：

**總部 AI 代理人**負責：
- 全品牌補貨預測與供應鏈協調
- 促銷指令與 SOP 更新推送至各分店
- 跨店異常偵測與根因分析

**分店 AI 代理人（超級店長）**負責：
- 即時戰情查詢：店長問「今天備料 + 訂單 + 設備狀態？」，AI 即時回覆結構化摘要
- SOP 語音問答：員工問「義大利麵醬汁加熱幾分鐘？」，AI 查詢本地 RAG 知識庫，附出處頁碼回覆
- 智慧叫貨：店長說「叫 200 顆雞蛋，裕成，明天到」，AI 自動建立叫貨單並推送總部確認
- 客訴上報：顧客回饋食材品質問題，AI 在授權範圍內啟動補救流程，並結構化上報總部

### 3. 全雲端 AI 推論架構

整個系統建構於 **GCP（Google Cloud Platform）台灣節點**，技術規格達到企業級水準：

| 指標 | 數值 |
|------|------|
| P95 推論延遲 | **< 150ms** |
| 端到端（含 NL2SQL） | **< 400ms** |
| GCP SLA | **99.95%** |
| 資料傳輸加密 | TLS 1.3 |
| AI 查詢架構 | 零原始數據（LLM 僅看 Schema） |

系統整合 WiXtar LaaS API（POS + KDS + 菜單管理），透過 **NL2SQL 自然語言查詢引擎（InsightVex）**，讓店長用口語問句即可取得跨系統報表，無需任何程式知識。

## 解決的核心痛點

### 痛點一：備貨靠直覺，報廢與缺料並存

**Before**：店長每日根據昨日銷量估計備貨，無法考量天氣、活動、假日效應。

**After**：AI 整合歷史銷售、即時天氣、商圈特性與活動資訊，每日自動產生備貨建議，店長確認後一鍵送出叫貨單，總部同步接收，**降低食材報廢率，提升叫貨準確度**。

### 痛點二：人員流動高，知識傳承斷層

**Before**：SOP 放在紙本手冊，新人訓練週期 3–4 週，店長異動即造成技術斷層。

**After**：所有 SOP、菜品知識、常見問答全部向量化進入 **RAG 知識庫**，員工透過語音或文字即可查詢，新人上線速度大幅加快，且答案標準一致、附出處可查證。

### 痛點三：尖峰時段系統分裂，第一線棄用

**Before**：POS、KDS、智取櫃各自獨立，尖峰時段店員需同時操作多個系統，複雜度導致放棄使用。

**After**：WiXtar POS / KDS / GraBox 智取櫃三系統透過統一 API 整合層串接，所有訂單事件（`order.created` / `kds.item_served`）透過 GCP Pub/Sub 事件總線即時同步，前台後場資訊流無縫銜接。

## 三場域驗證，從 MVP 到規模化

東方美與銓幻元採用三場域同步驗證策略：

1. **連鎖早餐店**：高峰出餐 / 預訂取餐 / 門市日常營運
2. **精緻餐酒館（駁二新品牌）**：訂位轉換 / 庫存備料 / 服務協作
3. **大宗物資批發**：訂單整合 / 補貨預測 / 供應鏈協同

Phase 1（1–3 個月）建立 GCP 基礎設施、完成 API 整合與首批文件向量化；Phase 2（4–12 個月）擴大門市複製，建立跨店告警機制與知識庫問答系統。
