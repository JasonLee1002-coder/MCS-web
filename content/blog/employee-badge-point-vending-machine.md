## 員工福利，正在從「發東西」變成「發點數」

過去講到員工福利，多數公司想到的是三節禮盒、生日禮券、部門聚餐。這些做法的共同問題是：**HR 和福委會的行政成本很高，員工的感受卻不一定好**——禮盒不一定合口味、紙本餐券要人工核銷、代訂下午茶要有人統計數量。

近幾年越來越多企業把福利「數位化」：與其發實體物品，不如把預算變成**福利點數**，讓員工自己決定什麼時候吃、吃什麼。而承接這些點數最自然的場景，就是公司裡的智慧販賣機——員工拿起識別證在機台感應一下，直接扣點取餐，不用掏錢包、不用掃碼、不用對發票。

這篇文章寫給 HR、總務與福委會夥伴：完整拆解識別證扣點販賣機的運作原理、點數制度怎麼設計、系統怎麼整合、報表怎麼對帳，以及導入要花多少時間。

## 識別證扣點是怎麼運作的？

很多人第一個疑問是：「門禁卡又不是悠遊卡，怎麼拿來買東西？」原理其實很簡單，整個流程分成三段：

### 1. 卡號綁定員工帳戶

台灣企業識別證絕大多數是 Mifare 或相容規格的感應卡，每張卡片都有一組**唯一卡號（UID）**。導入時，只要把「卡號 ↔ 員工工號」的對照表匯入雲端後台，每張識別證就對應到一個員工福利帳戶。員工不需要換卡、不需要下載 App、不需要註冊。

### 2. 販賣機感應扣點

員工在販賣機選好商品後，將識別證靠近機台的感應區，機台讀到卡號、向雲端後台查詢該員工的點數餘額，餘額足夠即完成扣點出貨，全程 2～3 秒。點數不足時，機台可依設定切換為行動支付或信用卡補差額（混合支付），也可以直接拒絕交易——規則由企業決定。

### 3. 後台自動記帳對帳

每一筆扣點交易都即時上傳 IVM 雲端管理平台，記錄「誰、什麼時間、在哪台機器、買了什麼、扣了幾點」。HR 不需要收集任何單據，月底直接從後台匯出報表，就是完整的福利使用明細。

> 一句話總結：**識別證扣點 = 門禁卡當錢包，但錢包裡裝的是公司發的福利點數，而且帳本自動生成。**

## 三種消費模式比較：現金、行動支付、識別證扣點

同樣是在公司裡放販賣機，員工用什麼方式付款，對 HR 的管理負擔差異非常大：

| 比較面向 | 現金投幣 | 行動支付 | 識別證扣點 |
|---------|---------|---------|-----------|
| 員工體驗 | 要準備零錢，深夜、產線環境不便 | 要拿手機掃碼，廠區可能禁用手機 | 感應識別證即完成，2～3 秒最快 |
| HR 管理負擔 | 無法補助，或需另發紙本餐券再人工核銷 | 需事後憑發票報帳，審核零碎單據 | 後台設定點數規則，全自動執行 |
| 補助發放方式 | 現金／禮券發放，流向無法追蹤 | 匯款補貼或代收代付，難以限定用途 | 每月自動入點，可限定於指定機台使用 |
| 報表對帳 | 需人工點鈔、對帳，有短溢收風險 | 依賴支付平台報表，與補助脫鉤 | 交易即報表，個人／部門明細一鍵匯出 |

簡單說：現金模式下福利「發不進去」，行動支付模式下福利「追不回來」，而識別證扣點是**發放、使用、對帳三件事在同一個系統裡完成**，這正是它最適合作為員工福利載體的原因。

## 福利點數制度怎麼設計？

系統只是工具，制度設計才是 HR 的主場。以下是實務上最常見的三層設計（金額均為示意，實際依企業預算調整）：

### 基本層：每月固定福利點數

- 每人每月固定發放一筆點數（示意：300～500 點，1 點 = 1 元）
- 定位是日常飲品、點心補貼，取代傳統的「茶水間免費咖啡」預算
- 可設定月底歸零（控制預算）或允許累積（提升滿意度），系統自動執行

### 加值層：情境式補助

- **加班宵夜補助**：與出勤資料串接或由主管核定名單，加班日自動加發宵夜點數（示意：每次 80～120 點），員工深夜在[冷凍微波販賣機](/products/frozen-microwave)扣點加熱一份熱食，比報帳買宵夜省事得多
- **夜班／輪班餐費**：針對特定班別員工設定專屬點數，解決夜班無餐可吃的老問題（延伸閱讀：[24H 工廠宿舍自助食堂方案](/blog/factory-dormitory-24h-meal-solution)）
- **部門活動點數**：取代「訂下午茶」的行政作業，直接發部門點數讓同仁自行取用

### 驚喜層：節慶與活動加碼

- 生日當月加碼、三節加碼、尾牙抽獎點數
- 業績達標、專案慶功的即時獎勵——比事後補請客更即時、更有感
- 點數發放在後台批次操作即可，幾分鐘完成全公司加碼

這套設計的精髓在於：**福利預算從「一次性大鍋飯」變成「高頻率小確幸」**。員工每天感應識別證消費時，都會再次感受到公司的福利，這種重複觸達的效果，是一年發兩次禮盒做不到的。

## 與門禁、HR 系統怎麼整合？

這是總務和 IT 最關心的問題。銓幻元科技提供三種整合深度，依企業資源選擇：

### 方式一：名單匯入（最輕量）

HR 從門禁系統或人事系統匯出「工號、姓名、部門、卡號」清單，以 Excel 匯入 IVM 後台即完成綁定。**不需要動任何既有系統**，人員異動時每月更新一次名單即可。100～500 人規模的企業多半用這個方式就足夠。

### 方式二：API 介接（自動同步）

IVM 平台提供 API 與企業的 HRM／門禁系統對接，實現：

- 新員工到職 → 帳戶自動開通、自動入點
- 員工離職 → 卡片即時停用，杜絕離職卡片盜用
- 出勤系統加班紀錄 → 觸發宵夜點數自動發放

### 方式三：混合模式

主檔用 API 同步，點數規則仍由 HR 在後台手動管理，兼顧自動化與彈性。

無論哪種方式，識別證扣點模組都同時支援銓幻元的智慧販賣機、[冷凍微波販賣機](/products/frozen-microwave)與 [GraBox 智取櫃](/products/grabox)——也就是說，飲料零食、加熱熱食、團膳取餐可以共用同一套點數帳戶，員工一張卡走遍全場域。

## 後台報表：HR 每月只要做一件事

導入識別證扣點後，過去最繁瑣的福利核銷作業，變成每月從 IVM 後台匯出報表：

- **個人明細**：每位員工的點數發放、使用、餘額，逐筆可查
- **部門統計**：各部門福利使用率，作為福利政策調整的數據依據
- **品項分析**：哪些商品最受歡迎，回饋給補貨與選品決策
- **公司補貼總表**：當月實際被使用的點數總額，即為福利支出的精確數字

### 稅務處理注意事項

福利點數屬於員工福利支出，實務上依「由福委會發放或公司帳發放」「金額大小」「是否屬伙食費性質」而有不同的帳務與所得認定方式。IVM 報表可完整呈現每人每月的發放與使用金額，方便會計人員分類申報。**建議導入前先與貴公司財會或會計師確認科目與扣繳處理**，避免年底才發現認定爭議。

## 導入流程與時程

以一間 200～300 人的企業為例，典型導入時程約 3～5 週（示意）：

1. **需求訪談（第 1 週）**：確認場域、機型（販賣機／冷凍微波機／智取櫃）、識別證卡片規格、預計的點數制度
2. **制度設計（第 1～2 週）**：HR 與銓幻元顧問共同確認點數規則——發放額度、有效期、補助情境、是否開放混合支付
3. **系統設定與綁卡（第 2～3 週）**：機台安裝、後台建置、員工名單與卡號匯入（或 API 介接開發）
4. **試營運（第 3～4 週）**：小範圍部門先行，驗證扣點流程與報表正確性
5. **全面上線（第 4～5 週）**：全員開通、公告使用方式，HR 從此每月只需匯出報表

若企業已經在使用銓幻元的販賣機或智取櫃，加裝識別證扣點模組的時程還會更短。至於「放一台販賣機取代部分人力服務划不划算」，可以參考[販賣機 vs 請人：成本效益完整比較](/blog/vending-machine-vs-hiring-cost-analysis)。
